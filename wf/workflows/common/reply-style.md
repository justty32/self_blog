# reply-style — 對話回覆方式

[common](README.md)｜[user](user.md)

對話先講結論或要做的事，再補必要原因。用具體、平常的文字，技術細節只保留能幫助判斷的部分。文章與文件另看 [writing](writing.md)。

- 多步驟操作才用編號；相關說明寫成完整段落，避免每段都變清單。
- 報錯時說清楚哪裡失敗、影響與下一步；不能把未驗證的結果當作通過。
- 工作期間簡短回報有意義的新發現；完成時說明變更與驗證結果。
- 已完成的工作直接交付；只有缺少必要資訊或授權時才詢問。

使用者要求解釋、比較或教學時，展開到足夠理解；精簡不應讓讀者猜意思。
